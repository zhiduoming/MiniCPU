## 一、视频开场（约 30 秒）

【画面：项目标题、开发板和显示器全景】

大家好，我们展示的是计算机组成原理课程设计项目。这个项目的核心，是在 Minisys FPGA 开发板上实现一个能够实际运行程序的 RISC-V 五级流水 CPU，并在它的基础上运行一个双人对战游戏。

这个游戏原本是我们之前数电课程设计中的项目，当时游戏逻辑主要由 Verilog 状态机直接完成。这一次，我们对它进行了重新拆分和迁移，让玩家移动、攻击、碰撞、血量和计时等主要逻辑真正由自己实现的 CPU 执行，VGA、按键和声音模块则作为 CPU 的外设工作。

接下来我们会从 CPU 的整体结构、主要模块、游戏迁移过程和最终运行效果四个部分进行介绍。

## 二、系统整体结构（约 1 分钟）

【画面：展示系统架构图】

整个系统可以分成三部分。

第一部分是 CPU 核心，包括五级流水线、寄存器堆、ALU、数据前推、分支预测、指令 Cache、乘除法扩展、乘加单元以及中断控制。

第二部分是存储和外设，包括指令存储器、数据存储器、MMIO、UART、性能计数器、矩阵键盘、板载按键、VGA 和蜂鸣器。

第三部分是运行在 CPU 上的游戏程序。CPU 通过 MMIO 读取玩家输入，计算新的游戏状态，再将玩家位置、血量、攻击状态、子弹位置和倒计时等信息写入 MMIO 寄存器。VGA 和音频模块读取这些状态，生成最终画面和声音。

开发板提供的输入时钟是 100 兆赫。当前 CPU 系统时钟是 5 兆赫，VGA 像素时钟是 50 兆赫。CPU 使用较低频率，主要是为了给当前的组合乘除法和其他数据通路留出足够的时序余量，优先保证上板运行稳定。

## 三、五级流水 CPU（约 1 分 30 秒）

【画面：展示 IF、ID、EX、MEM、WB 流水线图】

我们的 CPU 采用经典五级流水结构，分别是取指、译码、执行、访存和写回。

第一阶段是 IF，也就是取指。CPU 根据程序计数器 PC，从指令 Cache 或指令存储器中取出下一条指令，同时计算 PC 加 4。

第二阶段是 ID，也就是译码。译码模块会识别指令类型，找到源寄存器和目标寄存器，生成立即数，并由控制单元产生后续需要的控制信号。

第三阶段是 EX，也就是执行。普通加减法、逻辑运算、地址计算、分支判断、乘除法以及自定义乘加指令，都主要在这个阶段完成。

第四阶段是 MEM，也就是访存。Load 和 Store 指令会在这里访问数据存储器或者 MMIO 外设。

第五阶段是 WB，也就是写回。CPU 会从 ALU 结果、Load 数据、CSR 数据或者 PC 加 4 等结果中选择正确数据，写回目标寄存器。

五个阶段之间使用四组流水寄存器隔开。这样，多条指令就可以同时处在不同阶段。单条指令仍然要走完五个阶段，但是流水线填满以后，理想情况下每个周期都可以完成一条指令，从而提高整体吞吐率。

## 四、数据前推和流水线控制（约 1 分钟）

流水线会带来数据相关问题。例如第一条指令刚刚算出 x5，第二条指令马上就需要读取 x5。这时第一条指令可能还没有完成写回，如果直接读取寄存器堆，就会得到旧数据。

为了解决这个问题，我们实现了数据前推。冒险检测模块会比较当前指令的源寄存器和前面指令的目标寄存器。如果发现依赖，就从 MEM 或 WB 阶段直接把最新结果送回 EX 阶段，而不必等待正常写回。

除了普通 ALU 的两个输入，我们还实现了 Store 写数据前推、CSR 相关处理，以及自定义乘加指令所需要的第三路前推。

对于跳转、分支预测错误和异常中断，CPU会使用 Flush，把已经进入流水线但不应该继续执行的指令替换成空操作。对于人工暂停、CSR相关和中断处理过程，则通过 Stall 或 Bubble 控制流水线是否继续前进。

## 五、分支预测（约 40 秒）

【画面：展示两位饱和计数器状态图】

为了减少条件分支带来的等待，我们加入了一个两位动态分支预测器。它有强不跳、弱不跳、弱跳转和强跳转四个状态。

CPU在取指阶段先预测分支是否跳转，在执行阶段再得到真实结果。如果预测正确，流水线可以继续运行；如果预测错误，CPU会切换到真实目标地址，并清除错误路径上的指令。

当前实现是一个教学型预测器，所有条件分支共享一个两位计数器。它能够展示动态分支预测的基本过程，但没有实现更复杂的按地址索引预测表和分支目标缓存。

## 六、指令 Cache（约 50 秒）

【画面：展示直接映射和四路组相联对比图，或者展示 SW18】

取指部分加入了一个 128 字节的指令 Cache，共有 32 个指令槽。通过 SW18，可以选择直接映射或者四路组相联模式。

直接映射结构简单，但不同地址可能竞争同一个槽，产生较多冲突。四路组相联允许一个内存块在同一组的四个位置中选择，并使用近似最近最少使用策略决定替换位置，因此通常可以减少冲突缺失。

当前下级指令 ROM 是组合读取，所以 Cache miss 时，CPU可以直接使用 ROM 返回的指令，同时在下一周期完成填充，不需要暂停流水线。因此这个 Cache 主要用于展示地址映射、Tag、Valid、替换策略和命中率比较，而不是用来声称游戏获得了明显加速。

## 七、RV32M 乘除法扩展（约 1 分钟）

【画面：展示八条 RV32M 指令表和专项测试结果】

在基础整数指令之外，我们加入了完整的 RV32M 整数乘除法扩展。

乘法部分包括 MUL、MULH、MULHSU 和 MULHU。MUL返回乘积低 32 位，另外三条指令根据有符号和无符号组合返回乘积高 32 位。

除法部分包括 DIV、DIVU、REM 和 REMU，分别对应有符号和无符号的除法与取余。实现中还处理了除数为零，以及最小负数除以负一等边界情况。

这些指令复用了原有 R 型指令的数据通路，在 EX 阶段完成运算，再通过原有流水线写回寄存器。当前使用组合乘法、除法和取余，因此结构比较直接，但组合路径较长，这也是 CPU 使用 5 兆赫系统时钟的原因之一。

我们还准备了独立的 RV32M 测试程序。测试程序由 CPU 自己执行八条指令、比较实际结果和期望结果，全部正确后通过 UART 输出 OK。当前测试结果为 `M_EXT_RESULT: PASS`。

## 八、自定义 MAC 乘加单元（约 50 秒）

【画面：展示 MAC 公式和 2x2 矩阵测试】

除了标准 RV32M，我们还加入了一条自定义 MAC 乘加指令。它完成的运算是：目标寄存器原来的值，加上两个源寄存器的乘积。

也就是 `rd 等于 rd 加 rs1 乘 rs2`。这种运算经常出现在矩阵乘法、向量点积、卷积和数字信号处理中。

因为旧的 rd 既是输入又是输出，我们为寄存器堆增加了第三个读端口，并在流水寄存器、冒险检测和前推模块中增加了第三条数据通路。这保证了连续执行乘加指令时，累加器能够取得最新结果。

我们使用 2 乘 2 矩阵乘法进行专项测试，最终四个结果分别是十六进制的 24、29、40 和 49，仿真输出 `RESULT: PASS`。

这条指令是课程项目中的自定义扩展，最终游戏程序没有直接使用它，所以我们通过独立矩阵程序展示它的正确性。

## 九、简化外部中断和性能统计（约 1 分钟）

【画面：展示 SW20、PERF REPORT 画面和串口输出】

系统还实现了一个简化的机器外部中断。SW20 经过同步和 50 毫秒消抖后，会向 CPU 产生一次中断请求。

CPU接收到请求后，会保存当前执行位置到 mepc，将中断原因写入 mcause，再根据 mtvec 跳转到中断处理程序。处理结束后，通过 MRET 返回原来的程序。

在游戏中，中断处理程序不会直接完成耗时较长的串口格式化，而是先记录一个请求并尽快返回。游戏主循环在合适的位置读取性能计数器，在 VGA 上显示 PERF REPORT，同时通过 UART 输出周期数、退休指令数、分支预测错误数、Cache 命中率、访存次数和扩展指令次数等信息。

当前实现完成了课程项目所需的主要中断流程，但没有实现完整的 RISC-V 中断使能、挂起和优先级体系，因此我们把它称为简化机器外部中断。

## 十、游戏迁移过程（约 1 分 30 秒）

【画面：左侧展示原数电游戏结构，右侧展示迁移后的 CPU+MMIO 结构】

下面介绍游戏是怎样迁移到 CPU 上的。

原来的数电游戏中，玩家移动、攻击、碰撞和血量更新等逻辑主要由 Verilog 状态机完成，VGA 模块直接读取这些状态并绘制画面。这种方式可以运行游戏，但它本质上还是一个专用数字电路，不能证明 CPU 在执行游戏逻辑。

迁移时，我们首先把游戏拆成“状态计算”和“输入输出”两部分。原有的角色素材、背景、VGA绘制、按键扫描和声音模块可以继续作为硬件外设使用；玩家状态、战斗规则、计时和人机逻辑则转移到 CPU 程序中。

第二步是设计 MMIO 接口。我们为双人输入、玩家位置、血量和魔法值、攻击标志、子弹、药品和倒计时分别分配地址。CPU使用普通的 Load 指令读取按键，使用 Store 指令写入新的游戏状态。

例如，玩家按下向右键以后，键盘扫描模块先得到按键状态；CPU从输入地址读取这个状态，游戏程序增加玩家横坐标，再把新坐标写入玩家位置寄存器；VGA模块读取这个位置，在下一次画面刷新时把角色画到新的位置。

第三步是把原有游戏规则改写成 RISC-V 程序。当前项目使用 Python 脚本生成游戏机器码，程序会完成菜单选择、移动、跳跃、近战、投射物、碰撞、HP和MP更新、药品、比分、倒计时，以及人机模式的软件 AI。

最后，我们将生成的游戏程序写入 `program.hex`，由指令 ROM 在 FPGA 配置时加载。这样，VGA画面和游戏规则虽然看起来与原数电项目接近，但底层运行方式已经从专用状态机变成了“CPU执行程序，再通过MMIO控制外设”。

## 十一、上板演示（约 1 分钟）

【画面：开发板、显示器和串口窗口同屏拍摄】

现在进行实际上板演示。

首先，SW23 可以切换 VGA 彩条测试画面，用来确认 VGA 时序和颜色输出正常。切回游戏画面后，SW0 控制 CPU 运行，SW8 选择连续运行或单步模式，SW22 选择游戏输入模式。

玩家一使用矩阵键盘控制左右移动、跳跃、近战和投射物。玩家二在双人模式下使用五个板载按键。游戏支持人机对战和双人对战，也可以选择不同的比赛时长。

在战斗过程中，可以观察人物移动、攻击、血量和魔法值变化、子弹、药品、比分、倒计时以及对应音效。

触发 SW20 后，CPU进入中断处理流程，画面显示性能报告，串口输出本局运行期间的 CPU 和 Cache 统计信息。报告结束后，游戏继续运行。

## 十二、结尾总结（约 30 秒）

【画面：回到系统架构图或开发板全景】

以上就是我们的 CPU 和游戏迁移演示。

这个项目最终完成了一个可以在 FPGA 上运行实际程序的 RV32IM 五级流水 CPU，并将流水线控制、数据前推、分支预测、指令 Cache、乘除扩展、自定义乘加、中断、MMIO、VGA、音频和游戏程序整合成一个完整系统。

通过迁移原有数电游戏，我们不仅验证了单条指令，还验证了 CPU 在持续取指、访存、分支、处理中断和控制多个外设时的综合运行能力。

我们的展示到这里结束，谢谢大家。
