> 用途：为 MiniCPU 项目演示视频统一生成架构图、原理图和过渡画面。
>
> 建议工作流：先把“第一部分：项目背景资料”完整发送给生图工具，要求它作为后续所有图片的事实背景；然后按照第二部分顺序逐张生成。若生图工具不保留上下文，每次生成时把对应提示词中的“项目事实”一并发送。

## 第一部分：提供给生图工具的项目背景资料

### 1. 项目定位

项目名称为 `MiniCPU`，是一个在 Minisys FPGA 开发板上实现的 RV32IM 五级流水 CPU 小型 SoC。它不是普通软件应用，也不是直接用 Verilog 状态机完成全部游戏逻辑。

CPU 会从指令 ROM 中执行 RISC-V 游戏程序，通过 MMIO 读取矩阵键盘和板载按键，计算玩家位置、移动、跳跃、攻击、子弹、碰撞、HP、MP、比分、药品和倒计时，再把游戏状态写入 MMIO 寄存器。VGA 和音频硬件读取这些状态，生成画面和声音。

### 2. 硬件平台与时钟

- FPGA 开发板：Minisys，Xilinx Artix-7 系列。
- 板载输入时钟：100 MHz。
- CPU 系统时钟：5 MHz。
- VGA 像素时钟：50 MHz。
- VGA 输出：800x600，12 位 RGB。
- UART：115200，8N1，只实现发送主路径。
- CPU 使用 5 MHz 是为了给组合乘除法和较长组合数据通路留出更宽松的 FPGA 时序余量。

### 3. CPU核心

CPU采用五级流水：

1. `IF 取指`：PC、PC+4、指令 Cache、指令 ROM。
2. `ID 译码`：指令译码、立即数生成、寄存器读取、控制信号生成。
3. `EX 执行`：ALU、地址计算、分支判断、RV32M乘除法、自定义MAC。
4. `MEM 访存`：数据 RAM、MMIO、字节和半字处理。
5. `WB 写回`：把 ALU、Load、CSR、LUI 或 PC+4 结果写回寄存器。

阶段之间有四组流水寄存器：`IF/ID`、`ID/EX`、`EX/MEM`、`MEM/WB`。

### 4. 数据相关与流水线控制

- Hazard Unit 检测数据相关、控制相关和部分 CSR 相关。
- Forward Unit 支持 MEM/WB 到 EX 的数据前推。
- 普通 ALU 有 A、B 两路输入前推。
- Store 写数据有单独前推。
- MAC 因为旧 `rd` 也是累加器输入，所以增加第三路 C 输入前推。
- 跳转、分支预测失败和异常处理会使用 Flush 清除错误指令。
- 人工暂停、CSR处理和中断过程可能使用 Stall 或 Bubble。
- 当前数据 RAM 为组合读，因此没有传统同步 BRAM CPU 中固定的单周期 load-use stall。

### 5. 分支预测

- 使用一个全局两位饱和计数器。
- 四个状态：强不跳 `00`、弱不跳 `01`、弱跳转 `10`、强跳转 `11`。
- IF阶段先预测，EX阶段得到真实结果。
- 预测失败后，PC切换到真实目标，并 Flush `IF/ID` 和 `ID/EX`。
- 当前没有按PC索引的复杂BHT，也没有BTB。

### 6. 指令 Cache

- 只实现 I-Cache，没有 D-Cache。
- 总容量 128 B。
- 共32个物理槽，每条 Cache line 只保存一个32位指令字。
- SW18选择两种模式：32组直接映射，或8组4路组相联。
- 4路模式使用树形 pseudo-LRU 替换。
- 下级指令 ROM 是组合读，miss 时可以同周期旁路读取，下一时钟沿同步填充。
- 当前 `ic_stall=0`，I-Cache miss penalty 为0。
- 不能把该 Cache 描述为明显提升游戏速度；它主要用于展示命中、冲突、相联度、替换和性能统计。

### 7. RV32M乘除法扩展

支持完整八条标准M扩展指令：

- `MUL`：乘积低32位。
- `MULH`：有符号乘有符号，返回高32位。
- `MULHSU`：有符号乘无符号，返回高32位。
- `MULHU`：无符号乘无符号，返回高32位。
- `DIV`、`DIVU`：有符号和无符号除法。
- `REM`、`REMU`：有符号和无符号取余。

编码：`opcode=0x33`，`funct7=0000001`，`funct3=000..111`选择八条指令。

除零和溢出遵循RISC-V语义：

- DIV/DIVU除数为0时，商为 `0xFFFFFFFF`。
- REM/REMU除数为0时，余数为被除数。
- `0x80000000 / 0xFFFFFFFF` 时，DIV结果为 `0x80000000`，REM结果为0。

当前使用EX阶段组合 `*`、`/`、`%`，没有多周期busy/ready控制。

### 8. 自定义MAC乘加单元

- 语义：`rd = rd + rs1 * rs2`。
- 旧 `rd` 同时是累加器输入和结果输出。
- 自定义编码：`opcode=0x0F`，`funct7=0000001`。
- 寄存器堆增加第三读口。
- 流水寄存器、Hazard Unit和Forward Unit增加第三源 `rs3` 与C路前推。
- 通过2x2矩阵乘法专项测试。
- 测试矩阵结果：十进制 `36, 41, 64, 73`，十六进制 `24, 29, 40, 49`。
- 最终游戏程序没有执行MAC，MAC应通过矩阵专项图或仿真结果展示。

### 9. 简化外部中断

- SW20经过同步和50 ms消抖后产生外部中断请求。
- CPU锁存请求，保存返回位置到 `mepc`。
- `mcause=0x8000000B`，表示machine external interrupt。
- CPU读取 `mtvec`，跳转到中断处理程序。
- ISR只设置性能报告请求，随后执行 `MRET` 返回。
- 游戏主循环在安全位置读取PerfMon并输出报告。
- 当前没有完整实现 `mie`、`mip` 和可写 `mstatus` 中断控制，因此必须称为“简化机器外部中断”。

### 10. 存储器和MMIO

- 指令 ROM：8 KB，位于 `0x00000000` 区域，加载 `program.hex`。
- 数据 RAM：4 KB，位于 `0x10000000` 区域。
- UART TX：`0x10010000`。
- UART Status：`0x10010004`。
- PerfMon清零：`0x10010008`。
- 性能计数器：`0x10010020` 到 `0x10010050`。
- P1位置：`0x10010100`。
- P2位置：`0x10010104`。
- HP/MP：`0x10010108`。
- 游戏Flags：`0x1001010C`。
- 双人输入：`0x10010110`。
- 两个子弹位置：`0x10010114`、`0x10010118`。
- 药品位置：`0x1001011C`。
- 游戏倒计时：`0x10010120`。

### 11. 游戏迁移事实

原数电游戏：

- 游戏规则主要由Verilog战斗状态机直接执行。
- VGA模块直接读取HDL内部状态。

迁移后的游戏：

- 保留角色素材、背景ROM、VGA绘制、矩阵键盘、板载按键和音频作为硬件外设。
- 将菜单、移动、跳跃、攻击、子弹、碰撞、HP/MP、药品、比分、倒计时和软件AI迁移成CPU执行的RISC-V程序。
- Python脚本负责生成游戏机器码，输出到 `program.hex`。
- CPU通过Load读取输入，通过Store写入游戏状态MMIO。
- VGA与音频只消费CPU计算后的状态，不负责决定碰撞和扣血。

### 12. 视频视觉规范

所有生成图片保持统一设计语言：

- 比例：16:9，建议1920x1080。
- 风格：干净、平面化、现代工程信息图，不要科幻界面。
- 背景：白色或极浅灰。
- CPU：蓝色或青蓝色。
- 存储器和MMIO：绿色。
- 游戏程序：橙色或琥珀色。
- 控制、异常、中断：红色。
- Cache：紫色。
- 数据箭头：深蓝色。
- 控制箭头：红色虚线。
- 使用规则网格、直角连线、统一圆角和统一线宽。
- 禁止3D、透视、渐变光效、发光电路板背景、人物插画和无关芯片装饰。
- 一张图只表达一个核心问题。
- 每张图最多8到12个主要标签，避免超长句子。
- 中文必须准确，文字无法保证时应生成无文字底图，再在PPT、Figma或剪映中覆盖文字。

## 第三部分：不建议用AI生成的画面

以下内容应使用真实截图或实拍，否则容易造成证据不可信：

### 1. FPGA开发板与连线

使用手机或相机实拍 Minisys 开发板、VGA线、矩阵键盘、显示器和蜂鸣器。不要让生图模型伪造开发板照片。

### 2. 最终游戏运行画面

直接录制VGA显示器，展示菜单、双人/人机选择、移动、攻击、子弹、受击、药品、比分和倒计时。

### 3. SW20中断和性能报告

拍摄真实开关操作、VGA上的 `PERF REPORT` 和串口窗口。最好有一段画面同时拍到开发板、显示器和电脑串口。

### 4. RV32M测试结果

使用真实Vivado或Icarus终端截图：

```text
M_EXT_RESULT: PASS (OK)
```

### 5. MAC矩阵测试结果

使用真实仿真截图：

```text
MM 24 29 40 49
PASS
RESULT: PASS (MAC matrix)
```

### 6. Vivado综合和时序结果

使用真实的Utilization与Timing Summary截图，不要AI生成虚假数字。

## 第四部分：生成后检查标准

每张图片生成后按下面标准检查，不符合就要求工具局部修改，而不是整套重做：

1. 模块关系是否符合本项目，而不是通用CPU模板。
2. 游戏程序是否明确位于CPU执行的软件侧。
3. 是否把VGA画成输出设备，而不是游戏状态计算单元。
4. 是否把I-Cache误画成D-Cache或多级Cache。
5. 是否错误声称Cache miss会暂停或带来明显加速。
6. RV32M八条指令和funct3对应是否正确。
7. MAC是否包含旧rd作为第三输入。
8. 中断是否包含mepc、mcause、mtvec和MRET。
9. 中文是否存在错字、乱码或字形错误。
10. 一张图是否包含过多模块和交叉箭头。
11. 图片是否保持16:9和统一配色。
12. 是否出现虚构测试数据、开发板照片或Vivado界面。

如果生图工具中文文字不稳定，最稳妥的方法是：要求它生成结构、色块、箭头和图标，所有中文标签留白；然后在PPT、Figma、Canva或剪映中手工覆盖文字。对于技术架构图，文字准确性比“完全由AI生成”更重要。
